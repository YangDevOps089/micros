# Микросервисы

## Плюсы:
1. Независимые сервисы, которые могут работать, даже если упал «сосед».
2. Возможность автоматического увеличения ресурсов отдельного сервиса под нагрузкой и уменьшения мощностей в случае спада нагрузки (что ведёт к экономии денежных ресурсов).
3. Возможность разработки/доработки и деплоя отдельных сервисов, не затрагивая остальные.
4. Выбор технологии под каждый микросервис отдельно (исключает поиск компромиссов под все задачи).

## Что нужно решить:

1. На какие сервисы разделить монолит.
2. Как связать сервисы между собой и обезопасить передачу данных между сервисами.
3. Как централизовать мониторинг сервисов.
4. Как разделить ресурсы монолита (например, как разделить общую БД).
5. Подбор квалифицированных специалистов на обслуживание сервисов.
6. Продумать постепенный план миграции монолита на микросервисы.
